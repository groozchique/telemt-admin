# ADR 006: Управление WEB-профилями telemt при одобрении и удалении пользователя

## Статус

Принято (2026-10-30).

## Контекст

WEB-прокси telemt (3.5+) пускает пользователя только при наличии профиля в `[[web.vhosts]].profiles`. Создание пользователя через `POST /v1/users` профиль не добавляет. Профили — runtime-generation поля: watcher файла их не применяет, нужен `POST /v1/system/reload`. Кроме того, telemt отклоняет удаление пользователя, на которого ссылается профиль (`400 bad_request`, dangling profile).

## Решение

- `[web_proxy] manage_profiles = true` (по умолчанию `false`, только при `telemt_api.enabled`): после успешного `POST /v1/users` бот добавляет профиль `{user, secret_mode}` в vhost с `host`/`base_path` из `[web_proxy]`.
- При запуске (если `manage_profiles = true`) бот одним `PATCH` добавляет профили всем пользователям `tg_*` из `telemt`, у которых их нет: созданным до включения `manage_profiles`, через legacy fallback или при недоступном API.
- Перед удалением пользователя профили `tg_<id>` убираются из всех vhost независимо от `manage_profiles`, иначе удаление невозможно. Если `telemt` после этого не удалил пользователя, снятые профили возвращаются как были.
- Профили меняются через `GET` + `PATCH /v1/config` с `If-Match`: массив `web.vhosts` заменяется целиком, остальные поля vhost переносятся из `GET` как есть; при `409 revision_conflict` чтение и изменение повторяются (до 3 попыток).
- После изменения профилей бот вызывает `POST /v1/system/reload` с `mode = "drain"`, `timeout_secs = [web_proxy] reload_drain_secs` (по умолчанию 300), `failure_policy = "rollback"`. Пока идёт предыдущий reload (`409 reload_in_progress`), запрос повторяется в фоне каждые 15 с; несколько изменений объединяются в один reload.
- Вся работа с API — внутри `src/telemt_backend/` (`web_profiles.rs`), handlers не знают о профилях.

## Отвергнутые альтернативы

- Правка `telemt.toml` с диска (`toml_edit`) — бот в Docker не имеет доступа к файлу telemt; API-first (ADR 001).
- Отложенный reload (по расписанию или кнопке) — меньше разрывов, но новый пользователь ждёт WEB-доступ неопределённое время.
- `mode = "instant"` — без drain все текущие сессии рвутся сразу.

## Инварианты

- Ошибка добавления профиля не мешает выдаче обычной ссылки: она логируется, профиль можно добавить вручную.
- Бот не трогает vhost, кроме массива `profiles` нужного vhost.
- Reload не вызывается, если профили не изменились; `PATCH` без изменений не отправляется.
- Пользователь, оставшийся в `telemt` после неудачного удаления, сохраняет WEB-профиль.

## Последствия

- Каждое одобрение (при `manage_profiles`) и удаление пользователя с профилем пересоздаёт runtime-генерацию telemt: сессии старой генерации живут до `reload_drain_secs`, затем закрываются, клиенты переподключаются.
- `PATCH /v1/config` пересериализует секцию `[web]` в `telemt.toml`: комментарии внутри неё теряются, а значения по умолчанию (`[web.limits]`, `[web.debug]` и т.д.) записываются явно.
