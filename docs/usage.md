# Как пользоваться

## Для пользователей

1. Получите **пригласительный токен** у администратора.
2. Найдите бота и нажмите `/start`.
3. Введите токен или перейдите по ссылке вида `https://t.me/MyBot?start=TOKEN`.
4. Дальше всё зависит от типа токена:
    - Auto: бот сразу пришлёт ссылку на прокси.
    - Manual: бот создаст заявку («Ожидайте подтверждения») и пришлёт ссылку, когда админ её одобрит.

Если пользователь уже есть в `telemt` как `tg_<telegram_user_id>`, бот может сам добавить его в локальную БД при `/start`, `/link` и переходе по invite. Когда такой пользователь повторно переходит по invite-ссылке, `usage_count` не растёт.

На главном экране пользователя есть кнопка «✉️ Обратная связь»: следующее сообщение (текст или медиа, в том числе альбом) бот перешлёт всем администраторам из `admin_ids`. Ответ администратора приходит в этот же чат с кнопкой «✉️ Ответить», чтобы продолжить переписку. Если задан `[bot_messages] donation_text`, рядом появляется кнопка «💝 Пожертвование» с этим текстом.

Если у пользователя в `telemt` задан срок доступа или квота трафика, под ссылкой в `/link` (и по кнопке «Получить ссылку») бот показывает дату окончания, остаток дней и израсходованный трафик относительно квоты. Заранее он предупреждает и сообщениями: об окончании срока (по умолчанию за 3 дня и за 1 день), об истечении срока и о расходе квоты (по умолчанию при 90%), см. `[user_notifications]` в [configuration.md](configuration.md).

## Telegram Mini App

Mini App повторяет основные сценарии бота в веб-интерфейсе внутри Telegram. Открывается кнопкой меню рядом с полем ввода. Дизайн и границы безопасности описаны в [ADR 005](adr/005-telegram-mini-app.md).

- Пользователь видит статус доступа, обычную и WEB-ссылку (копирование, QR, «Подключить») и инструкцию по подключению, может отправить боту invite-токен. Если заданы срок или квота, на вкладке «Доступ» видны дата окончания, остаток дней и трафик. Там же форма «Обратная связь» (только текст, до 3000 символов; фото и файлы — через бота) и, если задан `donation_text`, раздел «Пожертвование».
- Администратор работает с заявками (одобрить или отклонить), пользователями (поиск, карточка, удаление), invite-токенами (создание, отзыв) и видит статус `telemt`. Опасные действия требуют подтверждения.

Как включить:

1. Задайте в `telemt-admin.toml` секцию `[webapp]` (см. [Конфигурация](configuration.md)): `enabled = true` и `public_url = "https://app.example.com/"`.
2. Опубликуйте `listen` (по умолчанию `127.0.0.1:8090`) через HTTPS reverse proxy, например Caddy: `app.example.com { reverse_proxy 127.0.0.1:8090 }`. Сервер приложения работает по HTTP, напрямую наружу его не публикуют.
3. Перезапустите `telemt-admin`. При старте бот ставит кнопку меню Mini App. Если порт занят, приложение не запускается. Если порт занят или `public_url` не задан либо не HTTPS, кнопка меню сбрасывается на стандартную. Бот в обоих случаях продолжает работать.
4. Проверьте `curl -fsS http://127.0.0.1:8090/healthz` и откройте приложение кнопкой меню в Telegram.

Безопасность: каждый запрос к `/api/*` подписан Telegram `initData` (HMAC-SHA256 на основе токена бота) и принимается не дольше `init_data_max_age_secs` (по умолчанию 1 час). Админские методы доступны только ID из `admin_ids`. Ответы API не кешируются (`Cache-Control: no-store`).

## Для администраторов

### Заявки

Когда приходит новая заявка (по Manual-токену), бот присылает сообщение с кнопками:

- **✅ Одобрить**: бот генерирует секрет, создаёт пользователя через control API `telemt`, сохраняет локальную запись в БД и отправляет пользователю ссылку. Если API не отвечает, возможен fallback на legacy-конфиг и `systemd`.
- **❌ Отклонить**: заявка отклоняется, пользователь получает уведомление.

В разделе `Заявки` список разбит на страницы, новые заявки сверху. Из карточки можно вернуться на ту же страницу.

### Токены

- `/token` открывает inline-меню invite-токенов: создание токена и список активных.
- Дни и лимит активаций при создании токена относятся **к ссылке-приглашению**, а не к сроку доступа пользователя в `telemt`. Срок доступа задаётся в карточке пользователя после регистрации.
- Список токенов разбит на страницы и отсортирован по сроку действия: сверху те, что истекают раньше.
- В списке токенов есть поиск по коду.
- Токен отзывают из его карточки.
- Созданный токен бот присылает готовой ссылкой вида `https://t.me/MyBot?start=TOKEN` и кодом в моноширинном формате.

### Админский интерфейс

После `/start` у администратора открывается главный inline-экран, постоянной reply-клавиатуры нет.
Основные разделы открываются slash-командами:

- `/start` — главный экран.
- `/user` — раздел пользователей.
- `/service` — компактная inline-панель управления `telemt.service`, control API и текущей нагрузкой.
- `/token` — inline-меню invite-токенов.
- `/link` — своя proxy-ссылка. Если у администратора ещё нет учётной записи, доступ будет создан автоматически.
- `/help` — список команд.

В списках пользователей и токенов есть поиск. Основные разделы админки устроены одинаково: список, карточка, действие, назад.

Новым пользователям доступ выдают через invite-токены. Раздел `/user` нужен для тех, кто уже есть: найти пользователя, открыть карточку, посмотреть deep link и QR, изменить лимиты или удалить доступ. Свою ссылку администратор по-прежнему получает через `/link`.

Если backend-операция не удалась, администратор получает причину отдельным отформатированным сообщением в чате.

Сообщения обратной связи от пользователей приходят всем админам из `admin_ids` с заголовком (ID, username, имя) и кнопкой «↩️ Ответить». Ответ уходит пользователю от имени бота.

Ещё в админке есть:

- `📢 Рассылка` — эксплуатационное сообщение всем пользователям со статусом `approved`;
- `📁 Группы` — создание группы, назначение пользователей, массовое отключение и общий срок группы;
- `📥 Импорт из telemt` — ручной импорт существующего `tg_<id>` из control API в локальную БД.

Действия в карточке пользователя:

- `🔄 Обновить` — перечитывает карточку и live-данные пользователя из `telemt` API.
- `🪄 Deep link` — присылает deep link, который через `/start` быстро открывает карточку пользователя.
- `🔗 Данные + QR` — присылает proxy-ссылку и QR-код, чтобы переслать их пользователю вручную.
- `TCP лимит` / `IP лимит` / `Квота` / `Истекает` — короткий wizard, который меняет лимиты пользователя через control API `telemt`.
- `⛔ Удалить пользователя` — удаляет пользователя из конфигурации `telemt`, деактивирует запись в БД и сообщает пользователю, что доступ отозван (`access_revoked_text`).
- `⬅️ Назад к списку` — возвращает на ту же страницу списка.

Если control API доступен, в карточке пользователя, кроме локальной записи из SQLite, видны live-данные из `telemt`:

- текущие соединения;
- active/recent unique IPs;
- трафик;
- действующие лимиты;
- expiration и `user_ad_tag`;
- sync-метаданные локальной БД;
- `invite_token_id`, если пользователь пришёл по invite;
- простые сигналы аномальной активности, если live-поля выходят за лимиты.

Действия в карточке токена:

- `🔄 Обновить` — перечитывает карточку токена.
- `🔗 Ссылка` — присылает готовую invite-ссылку для пересылки пользователю и короткую инструкцию, что делать дальше.
- `🗑 Отозвать токен` — деактивирует токен после подтверждения.
- `⬅️ Назад к списку` — возвращает на ту же страницу списка.

На сервисном экране рискованные действия (`Остановить`, `Перезапустить`) требуют подтверждения, а быстрые (`Обновить`, `Reload`) выполняются сразу. Там же есть:

- runtime snapshot по control API;
- сводка нагрузки (`uptime`, total/bad connections, handshake timeouts);
- live connections (`total`, `ME`, `Direct`, active users);
- sync-health по SQLite (`degraded`, `control_api`, `legacy`, top sync error codes);
- отдельный экран `📈 Top пользователей` по соединениям и трафику.

`/service` и экран top users переживают частичную деградацию control API. Если упал отдельный endpoint, бот не прячет весь экран: он показывает локальные данные, а причину ошибки пишет в том блоке, где она возникла.

Deep links для администраторов, кроме invite-token payload, умеют быстро открывать:

- карточку пользователя;
- карточку токена;
- основные admin screens через `/start`.
